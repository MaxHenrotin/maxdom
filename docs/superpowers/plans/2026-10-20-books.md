# Books Section Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a "Livres" part to the app: every Chroniques d'Aquilon volume, scraped weekly from monde-aquilon.com, drawn as a publication tree where a volume's circle grows into a card to tick it as read.

**Architecture:** The Worker scrapes the publisher's listing pages on its own weekly cron, upserts a `books` table in one statement, and serves the list, read ticks and live summaries under `/api/books`. The front end gets a "Séries | Livres" switch and a second module, `public/books.js`, that draws the tree as rows of absolutely placed lines and circles (the same technique as the approved prototype) and animates the card with CSS transitions.

**Tech Stack:** Cloudflare Workers + D1, Vitest with the in-memory D1 in `test/d1.js`, plain HTML/CSS/JS ES modules, no build step, no new dependency.

**Spec:** `docs/superpowers/specs/2026-10-20-books-design.md`. Approved interaction: `docs/superpowers/specs/2026-10-20-books-prototype.html`.

## Global Constraints

- Node 22: prefix commands with `PATH=~/.nvm/versions/node/v22.23.3/bin:$PATH` (system Node is 20).
- UI text in French; code, comments, commit messages in English. No mention of Claude in commits. Never push.
- No new npm dependency. Parse HTML with regular expressions or `HTMLRewriter`, not a parser package.
- The local D1 database is the only copy of the data. Before the first command that writes to it (Task 2, step 7), export it: `npx wrangler d1 export tvtime --local --output=data/backup-<date>-before-books.sql`.
- The books cron and the TVmaze cron run in separate invocations (50 subrequests per run on the free plan).
- Series, in column order: Elfes (`elfes`, #eab308), Nains (`nains`, #d97706), Orcs & Gobelins (`orcs-et-gobelins`, #16a34a), Mages (`mages`, #7c3aed), Terres d'Ogon (`terres-ogon`, #b45309), Guerres d'Arran (`guerres-d-arran`, #dc2626), Terres d'Ynuma (`terres-d-ynuma`, #0891b2). Short labels: Elfes, Nains, Orcs, Mages, Ogon, Guerres, Ynuma.
- Global order: publication date, then series in the order above, then volume number.

## Review Focus

1. A special edition listed with an earlier date than the standard one (Elfes T37 Édition NB on 05/11/2026, Elfes T37 on 12/11/2026): the tree keeps `elfes-t37` with 12/11/2026. Test in Task 1.
2. The site failing in the middle of the weekly scrape: what was fetched is saved, nothing is deleted, read ticks survive. Test in Task 2.
3. A summary request for an id that isn't a known volume (`../../wp-admin`, `foo`): 404 without fetching anything. Test in Task 3.
4. Ticking a volume that isn't out yet through the API: ignored. Test in Task 3.
5. The TVmaze cron still runs the TVmaze refresh after `scheduled()` starts dispatching on `controller.cron`. Test in Task 2.

**Interfaces:**

describe('refreshBooks', () => {
  it('saves the deduplicated catalogue and keeps what was read', async () => {
    const db = createD1();
    await db.prepare("INSERT INTO books (id, series, volume, title, published) VALUES ('elfes-t36', 'Elfes', 36, 'Old title', '2026-09-24')").run();

    const ids = (await db.prepare('SELECT id FROM books').all()).results.map((r) => r.id);

    expect(ids).not.toContain('elfes-t37-edition-nb');

describe('scheduled', () => {

Walk `SERIES` in order, fetching page 1 then the other pages with plain `fetch`. On the first failed response or thrown error, stop fetching and save what was collected (the next week retries). Save with a single statement, so the run uses one D1 query whatever the catalogue size:

```sql
INSERT INTO books (id, series, volume, title, published, cover_url)
SELECT value ->> 'id', value ->> 'series', value ->> 'volume', value ->> 'title', value ->> 'published', value ->> 'cover_url'
FROM json_each(?1) WHERE true
ON CONFLICT (id) DO UPDATE SET series = excluded.series, volume = excluded.volume, title = excluded.title,
  published = excluded.published, cover_url = excluded.cover_url
```

(`WHERE true` is how SQLite tells an upsert's `ON CONFLICT` apart from a join constraint.)

### Task 3: Books API

**Files:**
- Modify: `src/books.js`, `src/worker.js` (routing)
- Test: `test/books.test.js`

**Interfaces:**
- Consumes: `books` and `books_read` tables, `sortBooks` and `parseSummary` from Task 1.
- Produces:
  - `GET /api/books` → `Book & { released: boolean, read_at: string | null }` array in global order. `released` is `published <= today` (UTC date of the request).
  - `POST /api/books/read` `{ bookIds: string[], read: boolean }` → `{ ok: true }`; 400 on any other shape. Ticking ignores volumes that aren't released; `read_at` is the request time (ISO).
  - `GET /api/books/<id>/summary` → `{ summary }`; 404 when `<id>` is not in `books` (checked before any fetch); 502 when the publisher's page fails.
